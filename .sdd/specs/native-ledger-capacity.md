## Design
Reader inventory: readLedger(all its callers), native inspect, approvalProvenance, ledgerRegression and gateInputSnapshot use the qualified chunked parser/incremental hashing; mergeLedger remains legacy only below min(configuredLimit,64000000) input/output bytes and preflights larger work to exit2 unchanged. Use dependency-free native-ledger.mjs,64KiB file chunks/bounded Git bytes and no ledger-sized string; load it for TDD/approval too, retaining original chain/schema/evidence evaluators and caller BOM modes.
Policy: required:false retains prior disabled behavior; enabled absent=>64MiB; integer1..512MiB=>explicit total cap; invalid=>FAIL1; total/record cap or UTF-8/JSON/required-input failure=>INCOMPLETE2; invalid chain=>FAIL1. The model and missing-module CLI fallback enforce the same range; Git capture is bounded to configuredLimit+1 and truncated/failed output never proves absence.
Serialize each prospective event including LF before publication; under the existing ledger lock compare its record size and actual existing file size with the configured budgets. Check capacity before evidence publication; refuse overshoot instead of appending an unreadable history. Appending verification needs headroom; exact512MiB controls are read-only.
After exact-hash human approval, use a small-ledger tooling workspace with this identical spec and all five native TESTs; record canonical/copy and base/candidate hashes. Its gate is tooling evidence only. After frozen implementation/mutation review and separate human approval of the repository512MiB opt-in, promote exact reviewed bytes without transplanting its ledger; obtain genuine Root TDD, rebind/fresh-verify affected tasks and run the full project gate.
## Assumptions / risks
Keep the hard512MiB ceiling, default64MiB and unchanged EvidenceStore.maxRead64MiB receipt/log budget; no unlimited/auto-growth option. The new64MiB record cap prevents a single-string cliff; current largest record121276 bytes. The6-control run reached2583080KiB maximum process RSS, not a RAM cap or aggregate/future-data guarantee. The opt-in manifest must identify Node/platform, a human-approved RAM allowance with headroom above measured process/tree use, at least8GiB available memory at preflight and serial capacity commands; missing/insufficient resources block opt-in, and shared-host memory is not reserved.
The original787-event history and all appended events remain append-only: no compaction, rehash, split, fabrication or replacement. Preflight:1381 events/132433500 bytes. Preserve the exact prefix and all historical warnings/failures/manifests; spec/tool/config changes require actual affected-task requalification. Root stays explicitly128MiB until separate frozen-candidate approval.
Historical65/128MiB qualifications and the rejected256MiB proposal do not qualify this candidate. New isolated evidence: single-string512MiB failure reproduced; headroom-aware verification, exact512MiB check/fixture gate, streaming and bounded Git transport controls passed, with Root config/reader/CLI/ledger unchanged. Earlier prototype failures are retained. Integrated Git-baseline and append guards, final Native evidence for all five TESTs (genuine Red/Green for changed behavior), implementation review, Root receipts and full gate remain pending.
