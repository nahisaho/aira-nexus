## Design
API routes POST/GET /api/projects/:id/files and GET /api/projects/:id/files/:fileId/content enforce existing Entra/ownership; upload is a raw counted stream with encoded X-File-Name and decimal X-File-Size, bounded buffers,300-second abort and four active uploads/process (excess429). A project-row transaction reserves quota and metadata state; a server-only random object key uses ifNoneMatch*, then a fenced DB finalize records actual bytes/SHA/ETag. A failure never changes ready data; expired attempts are hidden and cannot finalize. GET list cursors encode time/UUID and never authorize access; consumers accept strict metadata and verify complete size/SHA before preview/download.
Azure SDK12.33.0 preserves tested Azurite API2026-06-06 compatibility. Production uses HTTPS account URL with managed identity; shared-key development configuration rejects all hosts except numeric127.0.0.1/::1 and rejects non-loopback endpoints before credentials are used. Disabled/missing storage returns503 without breaking projects. Explorer owns scoped metadata; each stable scope/file-ID-keyed viewer owns fetch/render cleanup, uses latest translated labels without effect-driven refetch, and unmounts while inactive. Existing WorkspaceTabs accepts a renderer. Images use inert data images; PDF.js6.5.438 per-view workers and local font/CMap assets keep CSP unchanged, no CDN. No live .env/DB/service edits are implied by spec approval.
Jobs use a separate PostgreSQL005 migration, repository/service/worker and shared typed state table. One transaction-scoped advisory lock serializes short queue mutations, quota checks and claims across processes; project ownership is rechecked in SQL and immutable owner/project fields bind every job. DB CHECK constraints and a composite owner/project foreign key with ON DELETE/UPDATE RESTRICT defend storage invariants; deletion/ownership transfer APIs remain out of scope. A claim creates one attempt/fence; no automatic retry/requeue. All timestamps use timestamptz(3), preserving exact millisecond cursor roundtrips. Job metadata holds timestamps/state/safe failure code; input is server-only JSON and no arbitrary handler result is persisted.
POST/GET /api/projects/:id/jobs, GET /api/projects/:id/jobs/:jobId and POST /api/projects/:id/jobs/:jobId/cancel use existing Entra/no-store/error envelopes. Successful cancel returns200 and the current job, accepts no body (400 otherwise) and is idempotent on terminal states. Precedence is auth401/403, project/malformed-job404, disabled503, enabled job-existence404, body413/JSON/schema/key/cursor/query400, idempotency409, capacity429. Project checks use only existing projects, never job tables. POST/list omit job-ID checks, so owned disabled routes return503 before body/query validation; all well-formed detail/cancel IDs do likewise while disabled. TEST-SVC-008/013 must cover all four disabled routes with005 unapplied and prove no job queries. POST returns a job; GET list returns {items,nextCursor}; detail/cancel return a job. Public job fields are id,projectId,type,state,createdAt,updatedAt,startedAt,finishedAt,cancelRequestedAt,failureCode (nullable times/code); no other fields. List accepts only cursor, no limit/other query fields (400); invalid/over256-char cursor is400. Cursor is canonical base64url JSON [millisecond ISO createdAt,UUID], ordering createdAt DESC/id ASC with timestamp ties/adjacent milliseconds tested.
A JobService registry validates input before enqueue; worker registries claim only known types. Canonical JSON uses JSON.parse semantics (duplicate raw keys: last wins), recursively sorted own object keys, ordered arrays and JSON.stringify finite JS numbers (-0 equals0,1.0 equals1); reject unsafe integer values, nonfinite numbers and __proto__/constructor/prototype keys recursively. Use no assignment into prototype-bearing accumulator objects. Different valid input/type at an existing key is409; invalid input is400 first. Unknown-type queued jobs remain visible/cancellable and count toward capacity; only cancellation releases their queue slot. Quota owner key is exactly (tenant_id,owner_oid), project key additionally includes project_id.
One worker runs at most one handler locally; multiple workers share global limits. No network/handler I/O holds the queue lock. Heartbeats observe cancel_requested and its fixed deadline; settlement before lease/deadline expiry acknowledges cancellation regardless of normal return/throw, without undoing side effects. Shutdown stops claims, aborts the handler and maps confirmed settlement of uncancelled work to failed/interrupted (never success); if it cannot settle within15 seconds its own process exits1 and lease recovery handles interruption. A fenced-out worker aborts immediately and cannot publish success.
## Assumptions / risks
Confirmed upload100MB=100000000 bytes and project10GB=10000000000 bytes; accepted preview limits are text/SVG1MB,PNG10MB/16MP,PDF25MB/200pages/16MP. Upload allowlist defaults to txt,csv,json,md,markdown,py,r,png,svg,pdf plus previously discussed docx,pptx,xlsx,jpg,jpeg (download-only unless opt-in conversion is enabled). Names/extension alone do not validate or execute contents. UTF-8 only; other encodings download. Unsupported/over-limit preview never rejects an otherwise valid stored file. No folder management, rename/delete, overwrite, share, file-content AI transfer, arbitrary execution or RAG; extraction is limited to the explicit docling-runtime/document-conversion contracts. The sole chat exception is the individually confirmed text/history transfer in the separately approved chat-consent/chat-runtime contracts; it never grants file access.
Upload state table: uploading->ready iff immutable commit+unexpired fence; uploading->failed on error; expired uploading cannot finalize; ready/failed are terminal. UI stages: loading/loaded/error and uploading/acknowledged/failed/interrupted; interruption is not proof of server rollback. Expiry frees logical quota, not guaranteed object-store cleanup: invisible failed/crashed blobs may remain until later fenced reconciliation; no automatic deletion/retention guarantee is claimed. Pagination is not a snapshot of concurrent additions. Large downloads buffer at most100MB in-browser; image/resource limits are defensive, not adversarial performance certification.
New schema and storage configuration need separate explicit backup/apply consent for the live environment; current services, real data and settings remain unchanged until then. No production Azure, live model call or real GitHub authentication is needed for verification. Native task plan/bindings, assertion Reds, production code, full gate and independent implementation review remain required after this design approval.
Spike evidence: session files/files-spike-{blob-stream,quota}.log plus files-spike-browser-proof.json; private Azure streaming, empty/mismatched/aborted writes, ETag/duplicate denial, real PostgreSQL quota races/owner fences/all6 transition rows and inert PNG/SVG/PDF under unchanged CSP passed. An initial Azurite log-oracle mismatch and obsolete PDFDocumentProxy.destroy call failed and are excluded; actual cleanup uses PDFDocumentLoadingTask.destroy, PDFWorker.destroy and Worker.terminate.

## Job state/event contract and counterexamples
The single typed production table enumerates all42 cells; "-" means refuse/no mutation. Events are claim, cancel, success (settled), error (settled), expiry, heartbeat and stop_ack (settled). A current-fence shutdown settlement uses error with failureCode=interrupted from running and the cancellation outcome from cancel_requested; TEST-SVC-013 verifies both and unconfirmed shutdown recovery.

| queued | running | cancelled | - | - | - | - | - |
| running | - | cancel_requested | succeeded | failed | failed | running | - |
| cancel_requested | - | cancel_requested | cancelled | cancelled | failed | cancel_requested | cancelled |
| succeeded | - | succeeded | - | - | - | - | - |
| failed | - | failed | - | - | - | - | - |

Job assumptions/risks: lease/cancel-deadline expiry fences DB writes but cannot physically stop arbitrary work or prove external side effects absent; concurrency limits govern valid DB claims, not orphan external operations. No hard-kill of other processes, exactly-once effects, automatic retries, priorities, retention/deletion, generic job UI/notifications/streaming/history or implicit runtime activation. The separately approved conversion-job-ui and chat contracts own their explicit scoped UI/history exceptions. ## Rich Markdown extension
User decisions: central rendered Markdown with TeX, Mermaid, PNG and SVG; automatic images only from the same project. Raw HTML/scripts and automatic external URLs remain forbidden. Existing non-Markdown previews/limits and all owner/integrity fences remain.
PASS/counterexamples: the existing Demo-style document renders headings/math/flowchart/local PNG/SVG under actual production CSP; hostile HTML/math/diagrams/URLs never execute, navigate or request external resources. Missing/ambiguous/oversized/active images fail locally; pagination and actual duplicate-name fixtures prevent arbitrary first-page/first-match resolution. Closing/switching destroys resources; Japanese labels, font settings and pane scroll remain. Native TEST-MDV-001..005, actual-CSP browser checks and isolated restored mutations required; NOT_RUN.
Design: React Markdown AST components with raw HTML disabled; packaged KaTeX with trust=false, bounded expansion/size and a DOM-free HTML-to-AST parser. Do not use its default browser template.innerHTML parsing, which violated the existing CSP in the first spike. Mermaid uses a dedicated opaque-origin sandboxed helper at /markdown-renderer.html, no allow-same-origin, credential transfer or API access; transferred MessageChannel validates protocol/limits and caller lifetime. Keep its bounded, noninteractive, unfocusable render frame offscreen, not display:none (sequence geometry requires a render tree). Parent policy changes ONLY from frame-src https://login.microsoftonline.com to frame-src https://login.microsoftonline.com <validated-publicOrigin>/markdown-renderer.html; preserve every other existing directive verbatim. This is a security-policy change requiring exact human specification approval, not a claim that the parent CSP is unchanged. The helper response must REPLACE the global CSP header with one confined policy: default-src 'none'; script-src 'self'; style-src 'unsafe-inline'; font-src 'self'; connect-src 'none'; img-src 'none'; frame-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'self'; sandbox allow-scripts. Never append a conflicting second policy or broaden other routes. Disable diagram clicks/links. Revalidate generated SVG without parent-DOM/CSS activation and display it as an inert image, never parent DOM. Do not claim that sandbox alone prevents a compromised child from navigating itself.
Image transport: preview PNG/SVG and generated Mermaid SVG use bounded MIME-specific base64 data: URLs, never blob: image sources, retaining existing img-src 'self' data:. Release image references on cleanup; this is separate from unchanged original-file download object URLs. Native/browser tests must verify real helper/parent response headers, allowed local data-image decode and denied non-helper frames, alongside existing Entra frame behavior.
Resource defaults: Markdown1MB; at most10000 parsed nodes/50000 post-transform nodes; at most100 TeX expressions of4096 code points with maxExpand1000/maxSize10; at most8 Mermaid blocks of8192 code points/max200 edges and1000000-byte/16000000-pixel output, each with a10-second observable deadline; at most32 distinct referenced images with existing per-image limits and20000000 compressed bytes total. Referenced PNG/SVG and generated Mermaid images jointly consume at most32000000 decoded pixels. Count before expensive rendering/allocation; failures are visible and original download remains. Limits are defensive, not adversarial CPU/process-isolation certification; iframe disposal is not a claim to terminate an OS process.
Relative image syntax accepts basename or ./basename, one canonical percent decode, exact stored case/name and .png/.svg only; reject other directories, URL schemes, protocol-relative/absolute forms, backslash, query and fragment. Scan at most100 scoped metadata pages/10000 ready records with existing cursor validation/abort; cursor cycles, duplicate IDs and budget exhaustion are visible image-resolution failures, not permission to select a partial first match. Detect all duplicate basenames before content fetch; cache verified referenced bytes only for the current viewer lifetime. Do not fetch referenced image content until metadata/type/individual and aggregate budgets are established. Repeated references share one validated resource.
Actual-browser command-shape feasibility includes a verbatim-production-CSP negative control (helper denied) and a positive candidate with only the exact helper frame source added. Markdown/table, measured inline/display TeX, synthetic PNG/SVG decode, opaque-origin/cookie isolation, Japanese flowchart/sequence, hostile label/image denial, invalid/over-budget diagram and cleanup passed; see .playwright-mcp/markdown-feasibility-v6.json. The earlier v4 prototype used a different parent policy and is NOT production-policy proof. Retain initial style-CSP, alias export, display:none, ESM launcher and probe DOMParser failures. This is not production asset resolution, final SVG validation, exhaustive hostile-input testing, full budget/deadline proof, native Green or release qualification; those remain required.
Naming intent: user requested AI-produced filenames use filename_projectID (extension remains last for the existing type allowlist). AI generation remains outside this implementation and existing/user files are never renamed or overwritten. A project ID alone cannot distinguish repeated same-name outputs inside one project; future producer collision allocation is deferred to that producer's contract. Until then ambiguous references explicitly fail rather than silently choosing the newest file. This is a conservative stated default, not a claim that filenames have become globally unique.
