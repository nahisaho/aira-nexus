# Durable text-only Copilot execution
Goal: independent server-owned generation survives browser disconnect/tab switch, with one active chat per user. Depends on chat-consent; durable-jobs-foundation is an explicit task prerequisite. No generic agent execution or broader Jobs UI.

## Design
Reuse JobWorker heartbeat5s/lease30s/cancel-deadline30s/shutdown15s, existing state table and current-fence completion adapter; no DB transaction spans SDK/provider I/O. A partial unique active-chat index and admission under the shared job advisory lock serialize both tenant/user axes; validity caps do not claim to stop orphan upstream compute.
Each run gets a new SDK process and state directory; no shared provider home/session resume or cross-owner pooling. Only fixed GitHub Copilot account/model/generation protocol traffic is permitted; no arbitrary endpoints, redirects/tool networking or diagnostics upload. Fail startup if required confinement/explicit configuration cannot be established; do not silently loosen enterprise policy.
Session config is the pinned offline spike's restrictive option set, allowedModels:[confirmedModel], streaming:true, infiniteSessions.enabled:false, no custom hooks/input handlers and deny-all permissions; unknown/tool requests fail closed. A bounded serialized writer assigns stable local SDK-event keys, never concurrently appends unordered callback promises, flushes before settlement and treats conflicting final-text reconciliation as failure; empty deltas do not consume text events, and byte/event/deadline limit violations fail without publishing the violating chunk. The300-second DB-time deadline starts at claim, includes discovery/startup/flush and never extends a job lease/cancel deadline.
GET /runs/:rid/stream?after=N emits only persisted{id,runId,sequence,type,text?,state?,failureCode?} events with SSE id=sequence and no auth token in URL; each page reauthorizes owner/project, sends keepalives without data at most every15s, and closes on terminal+drained events. SSE is a notification transport; paged durable events are the ordering oracle.
The browser reconnects from its last applied sequence, rejects gaps/contradictions, deduplicates replay and resumes via pages before live subscription. Stream errors after headers close the stream, never emit success or raw upstream errors. Client polling/backoff is abortable, one in-flight request, at least1s and at most30s between retries.
After a dispatched prompt, cancellation settlement requires the matching attempt's terminal SDK session.idle or session.error after local pending writes drain; abort RPC resolution is insufficient. Before prompt dispatch, confirmed closure of the attempt with no outstanding model-list/SDK request is sufficient. Connection/child exit without matching settlement is unconfirmed; cancel_requested can become cancelled only with this proof before all lease/cancel/run deadlines, otherwise expiry yields failed/cancellation_unconfirmed. Local settlement never proves upstream stop.
## PASS conditions and counterexamples
`REQ-CHR-001`..`REQ-CHR-006`: PASS cross-project/process same-owner busy and independent-owner controls, exact SDK option/content capture, zero-tool refusal, ordered writer/replay, matching-settlement partial cancellation and detached-browser completion; FAIL generic-job admission bypass, cross-owner runtime reuse, hidden send, unordered/duplicate text, abort-ack-only cancellation, old-session idle, settled-after-deadline, stale-fence append or crash retry. Native PostgreSQL/synthetic-provider/UI tests and bounded restored mutations are NOT_RUN.
## Assumptions / risks
Offline feasibility PASS: .sdd/chat-preparation-20261119/sdk-spike-attempt-6.log,7 assertion groups; real pinned runtime starts/creates/denies tools/aborts/disconnects without credentials or network. A loopback fake runtime exercises real SDK list/send/ordered-delta/idle/abort/detach shapes; no native prompt send or live provider request occurred.
Attempts1..5 are retained failures, not Greens. Native model entitlement, delivery, remote cancellation, egress/telemetry policy and real external retention are UNVERIFIED; local SDK idle plus abort/settlement is not a claim that upstream computation/billing stopped.
Defaults: reject a second pending chat rather than accumulate a queue; no silent output truncation or continuation/retry. Canonical DB history and private SDK history are not automatically purged; extra SDK-local plaintext/state storage and crash leftovers remain a disclosed operational risk, with deletion separately scoped.
