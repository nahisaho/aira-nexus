## Design
Separate ProjectPinsRepository and authenticated GET/PUT routes reuse project ownership and error envelopes; the existing Project JSON/API is unchanged. Migration006 creates project_pins(project_id PK/FK to original projects PK, pinned_at); ownership is derived by joining projects, never accepted from input. A transaction locks the owned project FOR UPDATE before insert-if-absent/delete; repeat pins preserve pinned_at and order, and writes never update projects. Production injection is gated by a strict optional PROJECT_PINS_ENABLED flag, default off.
Pin transition table [current,desired,next], 0=unpinned/1=pinned: `[[0,0,0],[0,1,1],[1,0,0],[1,1,1]]`; unauthenticated/foreign/missing/invalid/disabled/error requests leave state unchanged. GET/PUT returns current owned IDs in pinned_at-descending/id-ascending order; unknown/foreign/malformed IDs use existing project 404, unauthorized existing 401/403, strict body violations 400/413, disabled service 503/PROJECT_PINS_UNAVAILABLE, unexpected failures sanitized 500 with request ID/log. Enabling before006 yields sanitized500, never an empty success.
A session-keyed ProjectSidebar owns query/create form/confirmed pin state, abortable generation-fenced requests and focus restoration; App retains project mutation/selection authority. ProjectPinsApi reuses authorizedFetch and shared strict schemas. Focus reload does not race an active write; no timers, push channel, local persistence, job handlers or unrelated feature work.
ResizableWorkspace keeps expanded width state while rendering three visible grid tracks when collapsed; only the left content/handle disappears. App supplies collapse/expand buttons and keeps file workspace mounted. Collapse cancels unfinished capture before releasing focus; expanded bounds remain the existing workbench contract.
New accessible Radix dialogs remain controlled by the session/project scope; row action buttons are siblings, not nested in project-selection buttons. Existing App mutation/selection and epoch/owner fences remain authoritative; settings/trash APIs reuse authorizedFetch and strict schemas. Manager-capability false uses only legacy name CRUD with disabled description/trash and explicit reason, never a successful empty description; manager-read failure blocks writes rather than downgrading. Pin readiness remains independent. No author-entered text is interpreted as HTML.
PASS/counterexamples: focus/name+description/cancel/acknowledged create; row settings never selects; settings conflict and busy preserve committed data; trash/restore reload and clear current tabs only on acknowledgement; same-owner new-epoch and same-turn401 controls reject stale callbacks; Japanese/English and disabled-manager/pin matrices. Native TEST-DLG-001..004 plus real browser geometry/focus and restored mutations required; NOT_RUN.

## Manual order extension
User decisions: only within each existing group; server-backed per-user persistence across sign-in/devices. No cross-group drop or implied pin/unpin. Preserve existing pin API order/DTO and lifecycle APIs.
PASS/counterexamples: two groups remain separate; acknowledged move survives another client; foreign tenant/OID, trash, stale revision, failed save and old-epoch callbacks never move rows; mouse drag never selects/opens settings; keyboard gives equivalent results. Native TEST-SID-006..009 plus real browser pointer/focus and restored mutations required; NOT_RUN.
Design: separate default-off order capability GET /api/project-order/capabilities and GET/PATCH /api/project-order. GET returns strict {version,pinned,recent}; PATCH accepts only {group:"pinned"|"recent",projectId,beforeId:UUID|null}, plus quoted If-Match, and returns the acknowledged current snapshot. Every ID is checked against current active owned membership; order records never authorize projects. A per-owner order-state row serializes revision CAS; involved project row locks use deterministic ID order and membership is rechecked in a later READ COMMITTED statement. Never acquire the jobs lock after a project lock. Initial unsaved revision is1; PATCH atomically INSERTs an initial empty state ON CONFLICT DO NOTHING and locks it before CAS; the first successful move advances to2; upper bound2147483647.
Materialization/merge: each group initially has no saved ranks and reads its original default order. Before moving, prepend currently visible IDs absent from that group's saved array in their default order, then append the saved array including retained inactive/other-group positions; the displayed result filters this full sequence to current active owned group membership. Remove only projectId, require a non-null beforeId to be a different current visible member and present in the materialized sequence, and insert before it (null appends at full sequence end). Save the full materialized sequence, never a partial filtered/search list or splice(-1) fallback. Hidden entries keep relative positions; a previously ranked project re-entering that same group resumes its retained rank. Newly unranked members appear first; unrelated group ranks remain untouched. Revision changes only on successful manual moves: unrelated creates/pins/trash/restore do not invalidate a move whose involved IDs remain valid group members. Membership/anchor and initial-state controls are required in TEST-SID-007.
Migration009 stores owner-scoped order without changing project metadata; no dependency on005/007/008, but enabled order requires006 pins. The existing pre007-safe active predicate hides trash even after management rollback. Default-off routes return503/PROJECT_ORDER_UNAVAILABLE before order-schema queries. Ordinary errors retain confirmed order with visible retry/write blocking; only the exact disabled response is neutral unavailable.
Defaults/risks: until the first manual move in a group, keep the previous default order; afterwards retain relative manual positions across renames. Unranked projects appear first; trash retains stored positions and restore recovers them when membership is unchanged. No automatic "recently opened" history or real-time push; synchronize on load/focus and acknowledged local lifecycle/pin changes. Disable reordering during filtered search with an explicit reason, rather than silently repositioning hidden rows. Browser drag previews are not saved-success UI. A shared same-turn local-write guard prevents concurrent local reorder/pin/lifecycle writes; failed order reads block moves without disabling independently available unrelated features. Isolated PostgreSQL feasibility passed eight checks including first-move creation and an unrecorded anchor (order-spike-v3.json); this does not prove production/API/gesture/trash behavior. Mouse/keyboard/focus and the remaining state matrix require native/browser tests before implementation qualification.
Existing REQ/TEST IDs, approvals, native history and limitations remain. This is a new proposed revision, not an extension of the previous approval; source promotion,009/live flags and service operations require separately enumerated exact approvals. No live edits or restarts are authorized here.

## Project action menu and Archive terminology
The ellipsis remains the existing labelled row trigger, now with menu semantics. A Radix dropdown portal offers settings, the current pin/unpin action and Archive. Row pin remains a shortcut; existing hover visibility and drag behavior stay. No new dependency or API state is introduced. Settings contains only name/description editing and save/cancel; Archive is the current reversible trash operation, with localized sidebar/list/confirmation/error/footer terminology changed consistently. Internal `trash`, `trashedAt` and migration007 remain compatible.
The dialog hook uses one mode among closed/create/settings/archive-list/archiving. Archiving renders inline progress/error/retry only, never a modal. A single shared write guard covers capability readiness, fresh detail retrieval and the versioned trash transition; session/abort validity is checked again between detail and transition. Existing generation/session fences and acknowledgement-only callbacks remain authoritative. Menu close autofocus is suppressed only while a modal is opening; the existing connected-trigger/fallback focus mechanism also covers asynchronous menu actions without stealing focus moved elsewhere.

| State / event | Next state and invariant |
| --- | --- |
| Closed / open menu | Menu only; selection and data unchanged; Escape restores row trigger. |
| Menu / settings | Settings loads capability/detail, then ready or retryable error; menu closes without stealing modal focus. |
| Menu / pin-unpin | Menu closes, existing pin write guard/readiness and acknowledgement apply; no project selection. |
| Menu / Archive | Immediately enter guarded archiving; verify enabled capability and current detail/version, then transition without a popup or further click; duplicate/conflicting writes are blocked. |
| Create/settings / save | Pending blocks duplicates; acknowledged success closes and updates, failure retains inputs and retry; stale epochs never commit callbacks. |
| Archiving / acknowledgement | Remove/reload only the acknowledged project and its selected files; restore idle focus to the existing fallback after its row disappears. |
| Archiving / capability/detail/transition failure | Keep project/selection/files/pins unchanged; show localized inline error/retry and return idle focus to the connected row trigger. Retry repeats fresh detail/version retrieval before writing. |
| Archiving / stale or aborted detail | Do not start a transition; discard old success/failure and authentication callbacks. |
| Archive list / restore | Pending blocks duplicates; acknowledged success removes only that archived entry and reloads normal lists; failure preserves entries. |
| Any modal / cancel or Escape | Abort pending modal request, discard late outcomes, close and restore connected trigger/fallback; direct archive has no confirmation/cancel modal. |
| Any state / session change | Existing session-keyed unmount aborts and fences success/failure, including same-turn401; no prior-owner state crosses sessions. |
| Capability disabled/error | Disabled management exposes unavailable archive/description and legacy name-only editing; errors remain retryable without silent downgrade; pins remain independently usable. |
