# Offline bounded document converter
Goal: convert synthetic/owner-selected documents locally without executing author content or sending it to a model/provider. Source: confirmed phase-two decisions; file and job contracts remain in research-services.
| ID | EARS requirement | Test |
| --- | --- | --- |
| REQ-DRT-001 | When a supported document executes, the converter shall use pinned docling-slim2.150.0 (Python module docling) to produce UTF-8 Markdown and nonempty structured JSON for PDF,DOCX,PPTX,XLSX,PNG,JPG/JPEG, using Japanese/English OCR for images and scanned PDFs; unsupported, malformed, encrypted, partial or failed conversions shall return a sanitized failure, never successful empty artifacts or execution of macros/scripts. | TEST-DRT-001 |
| REQ-DRT-002 | If input exceeds25000000 bytes, a PDF exceeds200 pages, or execution exceeds300000ms from container start, then conversion shall fail explicitly without partial results or silent page truncation; source bytes must match stored size/SHA256/ETag before execution. | TEST-DRT-002 |
| REQ-DRT-003 | While converting, the runner shall use an immutable image ID, non-root UID65532, no network, read-only root/input/model mounts, dropped capabilities, no-new-privileges, CPU1, memory/swap4096MiB, at most96 PIDs and at most512MiB private writable tmpfs; no credential, database connection, host socket, ambient proxy environment or arbitrary host path/command shall enter the converter. | TEST-DRT-003 |
| REQ-DRT-004 | When conversion exits, the runner shall accept only a strict version1 JSON envelope containing canonical base64 Markdown/structured-JSON bytes, each at most25000000 bytes, with bounded70000000-byte stdout and65536-byte stderr; malformed, extra, oversized or non-success output shall fail, and raw document content, paths or diagnostics shall never be logged or returned as error text. | TEST-DRT-004 |

## Design
A server-side runner owns fixed argv Docker create/start/wait/kill/inspect/remove and owned-label discovery, private input staging and bounded IPC; the parser container never owns Docker/API/storage credentials. A shared versioned manifest owns exact IPC fields/limits/reason codes: success {version:1,markdownBase64,documentJsonBase64} with exit0, controlled failure {version:1,error:allowlistedCode} with exit2; every other frame/exit fails closed.
Shared reason allowlist: handler_failed,interrupted,cancellation_unconfirmed,invalid_input,unsupported_type,input_too_large,page_limit,invalid_document,conversion_failed,timeout,runtime_unavailable,output_invalid,output_too_large,source_unavailable,source_changed,quota_exceeded. No exception/diagnostic strings enter public responses.
Private verified input and read-only model cache enter a fresh container; only bounded stdout carries two encoded artifacts back. Parser scratch/OCR user-cache is private tmpfs; no output directory is extracted onto the host. Existing Blob/DB boundaries stay outside this container.
Lifecycle: created→running→exited→removed; abort from created/running requires confirmed stopped→removed, otherwise unconfirmed recovery, never a successful result. All failure paths preserve source and prior artifacts.
The host worker is trusted to access its container daemon; this is not a claim of kernel-level protection against a hostile host. Live runtime/image/model activation and downloads require separate operator approval.
## PASS conditions and counterexamples
`REQ-DRT-001`..`REQ-DRT-006`: valid6-format/ja-en controls; over25MB/201pages/time/memory, malformed/oversized IPC, wrong SHA/ETag, network/credential exposure, stale completion and unconfirmed stop must refuse with no published output; restored controls must succeed.
## Assumptions / risks
Defaults: outputs exclude extracted image files; Markdown references remain subject to the existing inert viewer. Each output is capped25MB independently; no OCR-accuracy or adversarial performance guarantee. Missing codecs/models are explicit failures, not text-only fallback.
Feasibility: phase2-docling-spike/readonly-ipc-report.json records exact argv and inspected read-only input/model mounts, bounded strict stdout envelope and successful6-format/OCR controls together as offline UID65532/CPU1/4GiB. runtime-attempt2.log proves byte/page bounds; lifecycle-shared-deadline.log proves inspected isolation, owned-label discovery and shared-deadline stop/removal. Initial metadata-name and read-only OCR mount probes failed and were excluded.
These synthetic scratch results are primitive feasibility, not production launcher/native TDD or permission to operate on live documents.
