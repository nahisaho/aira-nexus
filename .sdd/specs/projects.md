# Private persistent projects
Goal: persist only the signed-in user's projects. Non-goals: sharing, permanent deletion/purge, file-content execution and chat execution. Add owner-only project descriptions and reversible trash/restore.
The original PROJ requirements retain their existing /api/projects route scope and strict name-only inputs/DTOs; separate project-management routes below extend metadata/lifecycle without accepting description in legacy bodies.

## Design
API derives ownership from verified claims. Every SQL operation predicates tenant_id and owner_oid; JSON bodies cannot choose identity. Parameterized queries; immutable IDs; duplicate names allowed.
PostgreSQL owns durable state, CHECK constraints and compare-and-set rename. Separate migration command uses a transaction/advisory lock and refuses drift of an applied migration.
Management API: authenticated GET /api/project-management/capabilities → {enabled:boolean}; POST /api/project-management/projects {name,description?} →201; GET /api/project-management/projects/:id →200; PATCH same path {name,description} →200; POST same path /trash and /restore with empty strict JSON plus If-Match →200; GET /api/project-management/trash →200. Data responses are strict {project:originalProjectDTO,description,trashedAt:string|null}; trash returns {items:details[]}. Existing 16KiB reader and 400/401/403/404/409/413/428/error envelopes remain; malformed IDs are404, unexpected failures logged/sanitized500.
Transition policy [state,action,result]: active/settings→active+version; active/trash+idle→trashed+version; active/trash+busy→409 unchanged; trashed/restore→active+version; active/restore or trashed/trash→409 unchanged; stale/exhausted2147483647 version→409, absent→428, malformed→400, missing/foreign→404. Error precedence: authenticate, enabled/schema readiness, bounded strict JSON/UUID/version parsing, then owned resource/state lookup; malformed IDs are404 and resource404 assumes otherwise valid input. Trashed details are exposed only through owner trash-list/restore, never normal GET/PATCH; all conflicts preserve data.
Migration007 adds description/trashed_at without requiring005/006. A shared, always-applied PostgreSQL predicate (to_jsonb(project)->>'trashed_at') IS NULL accepts pre007 rows and denies trash after flag rollback, avoiding absent-column errors; all owner predicates remain. Management transactions acquire existing advisory key1747289124, then the owned project FOR UPDATE in one statement, then check active work in a subsequent statement at READ COMMITTED so a just-committed reservation is visible after a lock wait. Optional durable_jobs/project_files presence is checked inside the transaction; absent tables mean those features have no work. Upload reserve and finalization must share active-project row authorization; accepted uploads block trash until commit/failure/expiry.
PASS/counterexamples: strict old DTO still parses; 2000 supplementary code points accepted/2001 rejected; both owner axes denied; exactly one same-version writer wins; six job states enumerate three busy/three terminal; admission-first/trash-first and upload-finalize races never leave active work in trash; disabled write flag never re-exposes trash, including the pins.list JOIN and pins.set authorization (TEST-PMG-004 mutation targets). Native TEST-PMG-001..005 and restored bounded mutations required; not yet implemented.
