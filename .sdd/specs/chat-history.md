## Design
Additive migration014_chat_history.sql owns conversations, turns, previews, model-catalog snapshots, runs and events; every relation binds both owner axes/project, with composite constraints and immutable server UUIDs. No existing migration is edited or applied live.
Reuse durable job states/leases/caps and lock order advisory1747289124→owned project row→chat rows; chat input is only a run UUID, never a credential/transcript. Every chat.generate job transition, including generic /jobs cancel, any worker/owner expiry reconciliation and shutdown/lease failure, commits job/run/event changes through the same atomic adapter even when CHAT_ENABLED=false or its execution handler is unregistered; this transition adapter is independent of the opt-in execution registry. No chat row is read when no chat job is touched; if a touched chat job lacks required schema, fail sanitized and roll back all changes, never settle only its job. Expiry never accepts an expired worker fence. Every turn append/answer/status change increments conversation history revision; no network I/O holds these locks.
The existing single typed job transition table remains authoritative: queued cancel→cancelled; running cancel→cancel_requested; settled success/error from cancel_requested→cancelled; lease/deadline expiry→failed; all terminal writes refuse except idempotent terminal cancel. Native table-driven tests cover every existing cell plus chat side effects.
Authenticated /api/projects/:id/chat: GET /capabilities; POST/GET /conversations; GET /conversations/:cid; GET /conversations/:cid/turns; GET /runs/:rid and /runs/:rid/events?after=N; POST /runs/:rid/cancel accepts no body and returns the current run200, idempotent on terminal states. Public DTOs allow only IDs/role, model, text, state, safe reason, ISO-millisecond times, revision and sequence plus explicit pagination/capability/preview fields; never credentials, owner identifiers, SDK paths, raw provider errors, connection binding, fences or job input. Conversation detail includes latest/active run IDs for lost-response/reload recovery; cancel resolves the same owned job/state table.
Existing Entra/no-store/error envelopes remain. Precedence: auth401/403; active owned project/malformed-resource404; disabled503 without job/chat-table access; enabled readiness503/CHAT_UNAVAILABLE; enabled owned resource404; bounded body413/strict schema or query400; idempotent replay before new-preview validation409, owner-wide CHAT_BUSY409 before capacity429. Capabilities on an active owned project returns200 strict{enabled:boolean}, false without optional-schema access when disabled; enabled but unready returns503. Disabled routes do not distinguish well-formed unknown/foreign child IDs. Cursor/time/UUID checks match existing jobs; turns page100 ascending server turn sequence, never a browser-authored role.
Chat admission alone allocates the public (tid,oid,project,conversation,key) replay identity and internal job key chat:<runUUID>; generic /jobs registration must not admit chat.generate from arbitrary run IDs or bypass confirmed-preview consumption. Migration014 is applied only explicitly to disposable verification databases; API/worker startup never migrates. CHAT_ENABLED=true requires JOBS_ENABLED=true; missing owner connection remains an owner-scoped409, not a global enablement prerequisite, and document.convert remains independently opt-in.
## PASS conditions and counterexamples
`REQ-CHH-001`..`REQ-CHH-005`: PASS own empty/partial/full pages, restart, both-owner-axis404 controls, atomic admission/replay, gap-free events, retained cancelled partial and disabled chat routes pre005/pre014; FAIL cross-scope joins, generic-job bypass, duplicate turns/deltas, expiry/job-run divergence, terminal overwrite, lost history, disabled chat-route schema access or success-shaped readiness fallback. Tests above require actual disposable PostgreSQL races, both trash/admission commit orders, same-key cross-conversation controls, invalid-flag/schema-readiness cases and generic cancel/expiry of preexisting chat jobs under disabled/unregistered chat with atomic rollback if014 is missing; all NOT_RUN.
## Assumptions / risks
Defaults: server-generated display labels, no conversation naming; all canonical history stays in PostgreSQL without automatic deletion. Trashed project history is inaccessible until existing owner restore; active chat jobs already block project trash under its existing job lock.
Sequence parser accepts canonical decimal0..2147483647; future offsets return409, malformed/unknown query fields400, unknown/foreign runs404. Snapshot+lastSequence and paged events share a consistent transaction; concurrent additions are caught by a following read.
