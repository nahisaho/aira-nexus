## Design
Additive migration013 creates owner/project-bound requests with immutable source-UUID/name snapshots, unique active-source/automatic-origin guards and typed staged-artifact links; no source/artifact FK may block existing permanent purge. Original migrations/DTOs remain unchanged. The upload-ready transaction inserts its automatic outbox entry; a separate dispatcher, not the upload lock, acquires the existing job advisory lock for bounded admission.
Request persistence states are waiting, linked-to-job, failed-before-admission and cancelled-before-admission; only waiting may transition to another state, linked job state is canonical, terminal cancel is an idempotent no-op and other illegal transitions refuse. Active-source guards reconcile terminal jobs under the job lock before manual enqueue/admission; source/key replay/linking are atomic across restarts. Admission selects each uncapped owner's oldest waiting row, orders those heads by(created_at,id), bounds each scan to100 owner-heads and rechecks capacity per admission; no capacity idles at least1second.
The guard is an explicit request active:boolean with a unique(tenant_id,owner_oid,project_id,source_file_id) index WHERE active; it is not lifecycle state. Waiting cancellation/failure and worker settlement clear it atomically; reconciliation clears terminal linked-job guards and inserts a fresh request in the same job-locked transaction, without changing linked history.
Owner APIs: GET /api/projects/:id/conversions/capabilities→{enabled}; POST /api/projects/:id/files/:fileId/conversions with strict empty JSON/key; GET /api/projects/:id/conversions and GET /:conversionId; POST /:conversionId/cancel with no body. Auth/project/malformed-resource-ID404 precede disabled503 without querying conversion/file tables; when enabled, resource existence404 precedes input/key validation. Other envelopes/413/400/409/429 follow existing APIs.
Conversion requests waiting for admission are explicitly not queued/running jobs; they retain one small source pointer and consume no execution slot. History is retained; no automatic deletion is introduced. Source trash/removal before admission fails the request, and before publication prevents output visibility.
Verified outputs reserve quota as one pair, stage private immutable Blobs and commit both ready metadata plus successful job state under global-job-lock→project-row-lock order; expired reservations never publish or silently renew. A typed converter outcome settles only through the worker's completion adapter after heartbeat stops: one fenced transaction sets job state and request-side allowlisted reason/artifact links, rather than handler.run prematurely succeeding. Other handlers retain existing finish; crash/lease recovery reasons fall back to canonical job codes. No transaction spans Blob/conversion; prior cancellation wins; invisible staging Blobs may remain.
Names truncate the safe source basename to fit255 code points and include the full conversion UUID plus .md/.json. Artifacts remain ordinary ProjectFile values; history keeps immutable IDs, but read-time owner-scoped availability suppresses links to trashed/purged files without changing succeeded state.
## PASS conditions and counterexamples
`REQ-DCV-001`..`REQ-DCV-007`: upload+outbox commit/restart and queue-full controls; both owner axes, replay/active races, fairness, all request/job transition cells; exactly2-or0 visible outputs under lease/cancel/quota/Blob/SQL races; no source overwrite, ambient handler, automatic retry or disabled-schema query.
## Assumptions / risks
Confirmed: automatic upload conversion plus manual retry, Markdown+JSON in the same project, durable waiting under capacity/outage,25MB/200pages/5min limits. Defaults: no backfill; no bulk retry; preserve all successful generations; no extracted-image artifacts or external AI transfer.
Atomicity feasibility: phase2-docling-spike/atomicity.log passed durable waiting and paired SQL publication for success/cancel/expiry/partial rollback in disposable PostgreSQL. It does not prove production integration, Blob atomicity or concurrency; focused/native tests and restored mutations remain required.
