# Phase 2.1: user-owned Copilot connection and settings
Goal: retain Entra identity while each user connects their own GitHub account inside settings. This unit implements connection management; SDK chat integration remains unit 5.
| ID | EARS requirement | Test |
| --- | --- | --- |
| REQ-CON-001 | When an Entra user clicks the Settings gear at the bottom of the left pane, the system shall open an accessible modal with connection status and device-auth controls; closing, logout or identity change shall stop UI polling and prevent stale responses from exposing the previous user's settings. | TEST-CON-001 |
| REQ-CON-002 | When an authenticated user starts or polls GitHub device authorization, the system shall bind it to (tid,oid), expose only public attempt metadata/user_code, use https://github.com/login/device, enforce server-owned expiry/poll leases/slow_down, and explicitly report starting/pending/approved/denied/expired/cancelled/failed without allowing terminal or superseded attempts to bind credentials. | TEST-CON-002 TEST-CON-003 |
| REQ-CON-003 | If an attempt belongs to another identity or does not exist, then its API shall return the same 404; when the credential resolver has no current owner-bound token, it shall return connection-required without consulting environment tokens, CLI login or another user's connection. | TEST-CON-004 |
| REQ-CON-004 | When storing or disconnecting a connection, the system shall use authenticated owner/record/purpose-bound encryption, expose no device/access/refresh token, invalidate pending generations atomically on disconnect, delete local secrets, and require reconnection on known expiry or revocation; absent optional configuration shall disable only Copilot, while partial/invalid configuration shall fail startup. | TEST-CON-005 |
## Design
Existing Entra bearer middleware protects /api/settings/copilot: GET status/current attempt, POST /attempts (201), POST /attempts/:id/poll (200), DELETE /attempts/:id (200), DELETE connection (204). Identity comes only from verified claims; malformed/foreign/missing attempt UUIDs share 404. Starts have a per-owner 30-second cooldown; early/leased polls respect max(next_poll_at,lease_until); either limit returns 429 with Retry-After equal to the ceiling of its remaining seconds. Sanitized provider/protocol failures return 502; all settings responses are no-store.
One shared typed transition table owns states/events. Reserve starting before provider I/O; device_ready→pending, start provider_error/15-second deadline→failed; pending authorization_pending/slow_down/transport_error/protocol_error remain pending, access_token→approved, access_denied→denied, expired_token/deadline→expired, nonretryable OAuth configuration/grant errors→failed; starting/pending cancel/supersede/disconnect→cancelled. Terminal states never transition. Every owner operation reconciles overdue starting/pending records and clears their device secrets; subsequent starts may supersede them. TEST-CON-002 checks all state/event cells and guards.
PostgreSQL transactions serialize each owner and reserve a 15-second poll lease with a unique fencing nonce before network I/O. Approval rechecks current generation, matching unexpired lease, pending state and unexpired code, then atomically marks approved, clears device secrets/lease and replaces the owner's single connection with a fresh record UUID/nonce, removing the prior logical ciphertext. Disconnect increments the same owner generation, cancels unfinished attempts, revokes their leases and deletes the connection in that serialization. Stale completions cannot write and return that attempt's current public state; deadline wins over late approval. Network timeout is 10 seconds; pending expiry is min(900,provider expires_in) seconds from device-request initiation, never response receipt. No DB transaction spans network I/O.
Provider URLs are fixed GitHub.com device/code and oauth/access_token, redirects forbidden, URL-encoded POST and JSON responses capped at 16KiB. Poll interval starts at max(5,provider interval); slow_down uses max(previous+5,returned interval). Every poll result uses one generation/nonce-fenced commit to release its lease and set next_poll_at at least completion_time+interval and any provider Retry-After; transport/protocol failures double the retry wait per consecutive failure, resetting after a valid response. A crashed poll can be reclaimed only after lease expiry; unknown/invalid replies remain explicit retryable 502, never success. New attempts retain an existing connection until replacement succeeds.
AES-256-GCM uses a separately configured 32-byte base64 key, fresh 12-byte nonce and 16-byte tag; AAD binds tid/oid/record UUID/purpose. GET exposes only configured/disconnected/connected/reconnect_required plus safe attempt metadata; decrypt failures return sanitized 503, never erase evidence or imply disconnection. Disconnect deletes local secrets, not the upstream GitHub grant/subscription; PostgreSQL backups/MVCC are not claimed physically purged. The UI keys state by (tid,oid), discards it on identity switch/logout and never restores stale responses; the server attempt remains owner-bound and resumable until cancelled/expired.
GITHUB_OAUTH_CLIENT_ID and COPILOT_TOKEN_ENCRYPTION_KEY must both be absent or valid; do not extend the five-field public configuration. First integration targets an operator-owned OAuth App with device flow enabled and read:user scope, no client secret and no copied built-in client ID. Refresh tokens are discarded; local expiry/provider revocation requires reconnection. Connected means OAuth linked, not proven Copilot entitlement.
Downstream SDK boundary: pinned @github/copilot-sdk@1.0.31, explicit gitHubToken, useLoggedInUser:false, mode:empty, private baseDirectory/workingDirectory, availableTools:[] and source-specific ToolSet exclusions, deny permission requests. No host tools, Skills/MCP, shared provider home or token argv. This unit tests the owner-bound credential resolver; actual chat/stream/SDK token delivery is unit 5, not a claimed result here.
Dependencies: identity, projects, workbench, auth-popup. Real .env, GitHub registration, migrations of the running DB, service restart and real authorization remain operator-owned. Only isolated fixtures are authorized for implementation validation.

## Assumptions / risks
Defaults above require focused synthetic-provider/PostgreSQL/UI tests; no production completion or native Red/Green is claimed by this design. Closing the modal only pauses polling; explicit cancellation, supersession, disconnect or expiry terminates an unfinished attempt. Secrets are not browser-persisted or logged; cleanup nulls expired/terminal device secrets. Feasibility: real SDK 1.0.31 starts/creates/aborts/disconnects offline with ambient auth disabled; source-specific ToolSet filters are required (bare "*" is rejected). An empty offered tool list and native refusal of bash are checked separately from model execution. Auth/token/model streaming and real subscription/organization policy remain unverified; device-flow inputs follow official GitHub documentation. Shared-host spikes use capped containers and synthetic inputs, no inherited credentials; public dependency/model provisioning is separate from network-disabled runtime checks. AES key backup/rotation, upstream grant revocation and automatic refresh are operational follow-ups, not silently implemented here; key loss makes stored tokens unreadable. No arbitrary GitHub host/client-provided endpoint is supported.
