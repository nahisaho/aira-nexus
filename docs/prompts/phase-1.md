# AIRA Nexus 基盤実装プロンプト

以下は確定した要件を実装へ渡すプロンプト。今回の実行範囲は①のみ。
更新: 2026-11-12。再実行時は既存成果を読み、未完のタスクだけ進める。

## 実行する指示

あなたはこのリポジトリの実装担当です。機能比較、要件、全体設計を読み、Microsoft Entra IDで認証する研究支援Webサービスの基盤①を実装・検証してください。

### 正本と優先順位

`.sdd/specs/identity.md`、`projects.md`、`workbench.md`を今回の契約とする。
`.sdd/implementation-plan.json`を依存関係と検証進捗の正本とし、未来のdeferred機能を実装済みと扱わない。
`docs/architecture.md`と`.consulting/research-workbench/`を判断根拠として使う。参照コードは`references/`で読み取り専用とし、Gitに含めない。

### 確定した利用像

利用者は組織内の研究者・分析担当者。Entra ID単一テナントで、プロジェクトとデータは本人だけが使える。
将来は文献検索・出典付き回答、プロジェクトRAG、成果物とコードの追跡、R/Python Notebook、管理者承認済みSkills/MCPを備える。
AzureとオンプレミスのKubernetesへ共通配備し、AKSをAzure側の候補とする。目安は登録300人・同時50人・10GB/プロジェクトで、今回の性能達成を主張しない。
Mastraは中核候補だが採用未確定。既存Copilot／Claude／Codexの認証・契約・承認・中断の整合を検証するまで組み込まない。

### 今回実装するもの

TypeScript/React/ViteとTailwind CSSで3ペインUIを実装する。UI部品はRadix UIベースのshadcn/ui、アイコンはLucideを使う。
MSALによるサインイン・サインアウト、署名とclaimsを検証するAPIを実装する。
左ペインでプロジェクト作成・一覧・選択・改名、中央でチャット／ファイル／Notebookのタブ、右で将来のファイル探索領域を表示する。
本人のプロジェクトだけをPostgreSQLに永続化し、全クエリに検証済みtid/oidを含める。改名はversion比較で競合を拒否する。
チャット・ファイル・Notebookの未実装操作は無効化し、段階と制限を明示する。偽のAI応答や実行結果で完成を演出しない。

### Web UIの技術構成と実装方針

Tailwind CSSはViteプラグイン`@tailwindcss/vite`でビルドし、CDNや実行時のスタイル生成に依存しない。
shadcn/uiはRadix UIベースの構成を明示的に選び、Base UIベースの部品を混在させない。既存のReact/Vite構成を保持し、アプリ全体を再生成しない。
CLIのプリセットを生成前に確認し、生成後は`components.json`、部品のimport、依存関係がRadix UI構成であることを確認する。CLIの既定値を無条件に採用しない。
Button、Input、Label、Tabsなど、①に必要な部品だけをCLIで追加してリポジトリ内で管理する。追加するファイルと依存関係は実装前に計画へ反映する。
レイアウト・余白・文字・配色はTailwindのユーティリティと共通のテーマ変数で統一する。独自CSSはテーマ定義とユーティリティで表せない箇所に限定する。
左ペインの管理操作、中央ペインのタブ、右ペインの探索領域はshadcn/uiの部品を組み合わせる。独自のタブやダイアログでRadix UIのフォーカス管理を置き換えない。
LucideのReactパッケージ`lucide-react`を使い、装飾アイコンは支援技術から隠す。アイコンだけの操作には日本語のアクセシブル名を付ける。
キーボード操作、フォーカス表示、フォームのラベル、読み込み・エラー・無効状態を維持する。テーマ切替など未合意の機能は追加しない。
検証では部品の有無やCSSクラス名だけを確認せず、サインイン境界、プロジェクト操作、タブ移動、失敗表示を操作ベースで確認する。buildでTailwindのCSS生成も確認する。

### 守る境界

ブラウザは公開クライアントとし、Entra client secretを置かない。APIはIDトークンやGraphアクセストークンを受け付けない。
不明／他人のプロジェクトは同じ404。不正入力・競合・認証・サービス障害を明示し、秘密をログへ出さない。
本番の認証バイパス、共有資格情報、ホストの任意コマンド実行、プロジェクト削除や公開を追加しない。
既存の未追跡`.github/`を保持し、無関係な変更・コミット・pushをしない。

### 実行順と完了条件

仕様の反例・受入試験を先に用意し、独立レビューと必要な人間承認を得てからハッシュを固定する。
本物のassertion Redを記録し、最小実装でGreenにする。署名JWT、実PostgreSQLの所有者分離・永続化・競合、UI操作と失敗表示を検証する。
必要な箇所に限定した変異試験を戻した後、型検査・lint・format・build・テストとSDDゲートを実行する。
①の動作、環境変数、Entraアプリ登録、起動・マイグレーション、実施した試験と未検証事項をREADMEへ残す。
認証情報や外部基盤がなければ実SSO・配備試験を保留として明示し、モックやローカル試験を実接続成功と呼ばない。
